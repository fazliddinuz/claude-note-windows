# claude-note-win — Claude Code + ChatGPT Codex

Claude Code va ChatGPT Codex sessiyalaridan avtomatik bilim bazasi tuzadi.
Ikkala agent bir xil `vault/` dan foydalanadi: sessiya tugaganda yoki context
compact bo'lishidan oldin transkript qayta ishlanadi, yangi sessiyada esa loyiha
briefingi avtomatik kontekstga qo'shiladi.

## Codex bilan ishlatish

```powershell
python install.py
```

Installer mavjud sozlamalarni saqlagan holda quyidagilarni ulaydi:

- Claude Code: `~/.claude/settings.json` va `~/.claude/CLAUDE.md`;
- ChatGPT Codex: `~/.codex/hooks.json` (`SessionStart`, `PreCompact`, `SessionEnd`).

Codex xavfsizlik sabab yangi user hooklarini darhol ishlatmaydi. O'rnatgandan
keyin Codex ichida `/hooks` ni bir marta ochib, `claude-note` hooklarini
**Trust** qiling. `python install.py --status` ikkala agent holatini ko'rsatadi.

Codex transkriptlari `~/.codex/sessions/**/rollout-*.jsonl` dan o'qiladi.
`python note.py --backfill --limit 10` Claude va Codex tarixini birga ko'radi.
`synthesis_provider: "auto"` har bir transkriptni o'sha agentning CLI'i bilan
sintez qiladi; kerak bo'lsa `claude` yoki `codex` deb majburan tanlash mumkin.
`codex_model` синтез моделини белгилайди; стандарт қиймат `gpt-5.6-sol`.

Claude Code сессияларидан **автоматик билим базаси** тузади. Windows-native, WSL керак эмас.

`claude-note` (Mac/Linux, Python + qmd) ғоясининг Windows учун қайта ёзилган ва кенгайтирилган варианти.

## Тез ўрнатиш — 3 қадам

```powershell
# 1) Репони исталган папкага клон қилинг
git clone https://github.com/fazliddinuz/claude-note-windows.git
cd claude-note-windows

# 2) Hook'лар ва CLAUDE.md ни уланг (мавжуд созламалар сақланади)

# 3) Текширинг
```

Тамом: кейинги Claude Code сессияси тугаганда конспект `vault/` га ёзилади,
янги сессияда эса брифинг ўзи юкланади. `vault/` ва `state/` скрипт
ёнида ўзи яратилади — `config.json` да йўл ёзиш шарт эмас (ёзсангиз —
ўшаниси олинади). Жамоа сервери керак бўлмаса — шу ерда тўхтайсиз.

## Нима қилади

Сессия тугайди → hook ишга тушади → транскрипт ўқилади → `claude -p` (headless) уни конспект қилади → натижа мавзулар бўйича markdown файлларга тарқатилади → `INDEX.md` янгиланади → индекс `~/.claude/CLAUDE.md` орқали **кейинги ҳар қандай сессияга** автоматик юкланади.

Яъни билим йўқолмайди, ва Claude уни ўзи қайта ўқийди.

## Асосий хусусиятлар

| | |
|---|---|
| **Ягона глобал база** | Ҳар лойиҳага алоҳида эмас — бутун компьютер учун битта. Ҳар ёзувда `projects:` тэги бор. |
| **Ўзбек тилида** | Транскрипт қайси тилда бўлса ҳам, конспект `config.json` даги тилда ёзилади. |

| **Backfill** | Эски транскриптларни ҳам қайта ишлайди. |
| **Хавфсиз** | Hook блокламайди (фон жараён), хато Claude Code ни тўхтатмайди, рекурсия ҳимояси бор. |
| **Тежамкор** | Қисқа сессиялар (`min_user_messages` дан кам) ўтказиб юборилади, транскрипт `max_digest_chars` гача қисқартирилади. |

## Уч хил кесим

Бир хил билим уч томондан кўринади:

| Қаерда | Нима кўрсатади |
|---|---|
| `vault/notes/*.md` | **Мавзу бўйича** — барча сессиялардан келган фикрлар бир жойда. Вақт ўтиши билан тўлиб боради. |
| `vault/sessions/*.md` | **Ҳар бир суҳбат алоҳида** — ўша куни ўша сессияда нима бўлди, қайси эслатмаларга тушди, қанчага тушди. |
| `vault/projects/*.md` | **Лойиҳа бўйича йиғма** — ўша лойиҳанинг барча эслатмалари + барча сессиялари + умумий нархи. |

Учаласи `[[ҳавола]]`лар билан боғланган: лойиҳа саҳифасидан сессияга, сессиядан мавзу эслатмасига ўтиб кетаверасиз.

## Учта hook

| Hook | Қачон | Нима қилади |
|---|---|---|
| **SessionStart** | Янги сессия, шу жумладан `/clear` дан кейин | Лойиҳа **брифингини** контекстга юклайди. API чақирилмайди — текин ва бир зумда |
| **PreCompact** | Компакт тафсилотни йўқотишидан **олдин** | Ўша пайтгача бўлган билимни базага ёзади |
| **SessionEnd** | Иш тугади, `/clear`, `logout` | Қолган билимни ёзади |

`SessionEnd` нинг сабаблари: `clear`, `resume`, `logout`, `prompt_input_exit`, `other` — яъни **`/clear` ҳам hook'ни ишга туширади**, билим йўқолмайди.

Ишлов **босқичма-босқич**: `state/processed.json` да `lines_done` сақланади, шунинг учун компакт пайтида ёзилган қисм сессия охирида қайта ишланмайди ва **қайта пул тўланмайди**.

Битта савол-жавобдан кейин ҳеч нарса ёзилмайди (`Stop` hook атайин ишлатилмаган — жуда қиммат бўларди).

## Компьютерни дарҳол ўчирсангиз нима бўлади

Одатий ҳолат: VS Code ёпилди → hook ишлади → фон жараён синтезни бошлади (1–3 дақиқа) → сиз компьютерни ўчирдингиз. Жараён ўлдирилади.

Тизим бунга тайёр:

1. **Хом транскрипт дарҳол ёзилади** — API чақирувидан **олдин**, `vault/log/` га. Бу ҳеч қачон йўқолмайди.
2. **Job файли жойида қолади** (`state/job-*.json`) — фақат ишлов муваффақиятли тугагачгина ўчирилади.
3. **Кейинги сафар автомат тикланади** — `SessionStart` hook ярим қолган ишларни кўради (2 дақиқадан эски бўлса) ва фонда қайта ишга туширади. Сиз ҳеч нарса қилмайсиз.
4. `lines_done` фақат муваффақиятдан кейин сақланади — яъни ярим қолган иш «бажарилди» деб белгиланмайди.
5. 3 марта уринишдан кейин ташлаб юборилади (`state/note.log` да ёзилади), акс ҳолда чексиз айланарди.

Қўлда ҳам ишга туширса бўлади:
```powershell
python note.py --catchup
```

**Хавфсиз одат:** VS Code'ни ёпгач 1–2 дақиқа кутинг. Кутмасангиз ҳам йўқолмайди, лекин синтез учун бир марта қайта тўланади (агар API чақируви ярмида узилган бўлса).

## Брифинг — `/clear` ни арзон қиладиган нарса

`/clear` нинг камчилиги: контекст йўқолади ва қайтадан тушунтиришга вақт кетади. Шунинг учун ҳар бир лойиҳа учун **брифинг** ёзиб борилади: `vault/projects/<Лойиҳа>-brief.md`.

Ичида фақат **доимий** маълумот: тизим тузилиши, технологиялар, муҳим йўллар, келишилган қоидалар, тузоқлар. «Бугун X ни тузатдик» каби вақтинчалик нарса эмас — у эслатмаларга кетади.

`SessionStart` hook уни автомат контекстга юклайди. Натижа: `/clear` дан кейин 350k контекстни қайта тиклаш ўрнига 3–5k лик брифинг келади.

## Тавсиялар

Ҳар сессиядан кейин Claude **иш усули** бўйича маслаҳат ёзади (иш натижаси ҳақида эмас): контекст шишганими, бир сессияда аралаш мавзулар борми, олдиндан айтилса вақт тежайдиган нарса борми. Ҳаммаси `vault/TAVSIYALAR.md` да.

## Нархни тушириш

`note analyze <session-id>` — сессия нимага қиммат тушганини кўрсатади ва аниқ тавсия беради.

Ўлчанган мисол: 2,699 сўровли сессия $674 га тушган, шундан **$503 (75%) кэшдан қайта ўқишга**. Медиан контекст 349k, макс 998k эди. Ҳар бир `Bash` чақируви ~$0.19 турган — буйруқ учун эмас, олдинги контекстни қайта ўқиш учун.

Ричаглар:
1. **Мавзу орасида `/clear`** — брифинг борлиги учун энди арзон. Медиан 349k → 50k бўлса, $503 → $67.
2. **`autoCompactWindow`** созламаси (ёки `CLAUDE_CODE_AUTO_COMPACT_WINDOW`): `auto` ўрнига `200k` қўйилса, компакт тез-тез ишлайди, контекст кичик қолади. `PreCompact` hook борлиги учун билим йўқолмайди.
3. **Bash буйруқларини бирлаштириш** — ҳар чақирув алоҳида сўров.
4. **Оддий ишларда Sonnet** — кэш ўқишда 2.5 баробар арзон.

## Учта режим (`config.json` → `mode`)

- **`log`** — фақат хом транскриптни сақлайди. `claude -p` чақирилмайди, текин.
- **`inbox`** — конспект битта `inbox.md` га тушади, ўзингиз тартиблайсиз.
- **`route`** — конспект мавзу бўйича керакли `notes/*.md` файлга ўзи тарқалади. **Тавсия этилади.**

## Харажат ҳисоби

Ҳар бир сессия учун **иккита нарх** ёзиб борилади:

| | Нима | Қаердан |
|---|---|---|
| **Иш нархи** | Ўша сессияда Claude билан ишлаганингиз қанчага тушган | Транскриптдаги ҳар бир сўровнинг токен ҳисоби × расмий нархлар |
| **Эслатма нархи** | Ўша ишни билим базасига ёзиш қанчага тушган | `claude -p` нинг `total_cost_usd` майдони |

```powershell
python note.py --costs      # лойиҳалар бўйича жадвал
note costs                  # қисқа варианти
```

Батафсил ҳисобот `vault/COSTS.md` да — лойиҳалар кесимида ва охирги 40 сессия бўйича. Хом дафтар: `state/costs.jsonl`.

**Муҳим:** обуна (Pro/Max) билан ишлаганда ҳақиқий пул ечилмайди — сарф лимитдан кетади. Бу рақамлар «агар API билан ишлаганимизда қанча кетган бўларди» саволига жавоб.

Нархлар (`$/1M токен, PRICING`): Opus 5 / 4.8 — $5 кириш, $25 чиқиш · Sonnet 5 — $2/$10 · Haiku 4.5 — $1/$5. Кэш: ёзиш 5m = 1.25×, 1h = 2×, ўқиш = 0.1× кириш нархи.

Codex учун расмий OpenAI Standard API нархлари ҳисобланади: GPT-5.6 Sol —
$4 кириш, $0.40 кэш ўқиш, $5 кэш ёзиш, $20 чиқиш; Terra —
$2/$0.20/$2.50/$12; Luna — $0.20/$0.02/$0.25/$1.20. Бу ChatGPT
обунасидан ечиладиган пул эмас — айнан шу иш API орқали бажарилгандаги
тахминий қиймат.

Транскриптда битта сўров бир неча марта ёзилиши мумкин (retry, sidechain) — `requestId` бўйича дублиқатлар ташланади, акс ҳолда нарх икки баробар кўп чиқади.

## Жамоа ҳисоботи (телеметрия)

Жамоа битта Claude аккаунтидан турли жойлардан ишлайди. Аккаунт битта бўлгани
учун Claude томонидан «ким ишлаяпти» деган саволга жавоб йўқ — шунинг учун
ҳар бир компьютер **ўзи** ким эканини айтиб юборади.

**Стандарт ҳолатда ўчиқ.** `telemetry_enabled: false` бўлса ҳеч нарса
йиғилмайди ҳам, юборилмайди ҳам.

### Нима юборилади

Битта сессия учун битта ихчам ёзув — **~700 байт**:

| Майдон | Нима |
|---|---|
| `member`, `host`, `os_user` | ким, қайси компьютерда, қайси Windows юзери остида |
| `project`, `session`, `date`, `event` | қайси лойиҳа, қайси сессия, қачон, қандай ҳодиса |
| `agent` | сессия `Codex` ёки `Claude Code` орқали бажарилгани |
| `started_at`, `ended_at`, `tz_offset_min` | сессия қачон бошланиб қачон тугаган (UTC + маҳаллий фарқ) |
| `title`, `summary` | сессия сарлавҳаси ва қисқа хулосаси (тозаланган) |
| `requests`, `models`, `avg_context` | сўровлар сони, моделлар, ўртача контекст ҳажми |
| `work_cost_usd`, `note_cost_usd` | иш нархи ва эслатма нархи |
| `tools` | қайси tool неча марта ишлатилган — фақат **номи** |
| `notes_added`, `lines` | билим базасига қанча ёзилди, транскриптнинг қайси оралиғи |

Веб ҳисоботда **Agent** фильтри орқали Codex ва Claude Code натижаларини
алоҳида кўриш мумкин; фильтр статистика, моделлар, tool'лар,
огоҳлантиришлар ва сессиялар рўйхатига бир хил қўлланади.

### Нима ҲЕЧ ҚАЧОН юборилмайди

- хом транскрипт, суҳбат матни, сизнинг саволларингиз
- код, файл мазмуни, tool натижалари
- tool аргументлари (bash буйруқлари, файл йўллари, қидирув нақшлари)
- тўлиқ файл йўллари, IP манзиллар, калит/токенга ўхшаган сатрлар

Серверга чиқадиган ҳар бир эркин матн `scrub()` дан ўтади:

```
D:\demo-project\app\core\models.py да хато    →  …/models.py да хато
сервер 203.0.113.10 га уланди                →  сервер «сервер» га уланди
токен sk-ant-api03-QWErty12345 ишлатилди     →  токен «калит» ишлатилди
```

Хулоса умуман керак бўлмаса: `telemetry_send_summary: false` — унда фақат
рақамлар кетади.

### Сервер

Сервер — шу репонинг [`server/`](server/README.md) папкаси (FastAPI +
SQLite, дашборд парол билан). Уни икки хил ишлатиш мумкин:

- **(а) Ўз компьютерингизда** — бир киши ёки офис ичида. Docker шарт эмас:

  ```powershell
  cd server
  python -m pip install -r requirements.txt
  $env:INGEST_TOKENS = "узун-тасодифий-токен"
  $env:DASHBOARD_PASSWORD = "парол"
  python -m uvicorn app:app --host 127.0.0.1 --port 8095
  ```

  Дашборд: <http://127.0.0.1:8095> (логин `admin`). `config.json` →
  `telemetry_url`: `http://127.0.0.1:8095/ingest`. Docker бўлса:
  `copy .env.example .env` → `.env` ни тўлдиринг → `docker compose up -d --build`.

- **(б) VPS'да жамоа билан** — Docker + nginx + HTTPS. `.env` ни
  тўлдирасиз, `bash deploy.sh <ssh-алиас>` кодни серверга чиқаради,
  `nginx.conf.example` ва `certbot` билан `https://your-server.example.com`
  очилади. Мижозлардаги `telemetry_url`:
  `https://your-server.example.com/ingest`.

Батафсил: [`server/README.md`](server/README.md). Сервер манзили ва
токенлар ҳеч қаерда қаттиқ ёзилмаган — уларни ўзингиз тўлдирасиз.

### Жамоа пакети қандай тайёрланади ва тарқатилади

Олдиндан (бир марта, эга томонида):

1. Сервер ишлаб турибди (юқоридаги (а) ёки (б)).
2. `config.json` → `telemetry_url` га сервер манзилини ёзинг.
3. Сервер VPS'да бўлса — `config.json` → `server_ssh` (SSH алиас) ва
   `server_dir` (сервердаги папка, стандарт `/opt/claude-note-server`).
   Шунда `note paket` токенни рўйхатга қўшадиган тайёр буйруқни ёзиб беради.
4. `JAMOA.md` даги сервер манзилини (`your-server.example.com`) ўзингизникига
   алмаштиринг — бу ҳужжат пакет ичида жамоадошга боради.

### Жамоа аъзоси қандай уланади — битта тугма

Сиз (эга) битта буйруқ билан унга тайёр пакет ясайсиз:

```powershell
note paket "Алишер"
```

Бу нима қилади:

- `state/paket/claude-note-алишер.zip` яратади — ичида керакли ҳамма нарса,
  шахсий токен ва ўзбекча `OQING.txt`;
- серверда токенни рўйхатга қўшадиган **тайёр буйруқни экранга ёзади** —
  нусхалаб ишлатасиз.

Ҳар кимга **алоҳида токен** берилади: одам ишдан кетса фақат унинг токени
ўчирилади, қолганлар ишлайверади.

Тарқатиш: zip ни жамоадошга исталган йўл билан юборинг (Telegram, почта,
флешка). Унда шахсий токен бор — очиқ чатга ташламанг. Дашбордга кириш учун
логин/паролни **/users** саҳифасида алоҳида яратиб, бошқа хабарда беринг.

Шерик томонида қиладиган иши — иккита қадам:

1. zip ни очиш;
2. **`ornat.cmd` ни икки марта босиш.**

Тамом. `ornat.cmd` ўзи: Python борлигини текширади (йўқ бўлса нима қилишни
ёзади), учта hook'ни рўйхатдан ўтказади, исм ва токенни жойига ёзади,
сервер билан алоқани текширади ва ҳолатни кўрсатади. Ҳеч нарса сўралмайди —
исм ҳам, токен ҳам пакетда бор.

Интернет ўша пайтда бўлмаса ҳам ўрнатилаверади: ҳисоботлар навбатда кутади.

**Қўлда улаш** (пакетсиз, репони клон қилиб):

### Жамоа аъзоси қандай уланади (қўлда)

1. Репони клон қилиб `python install.py` ни ишлатинг.
2. `state/config.local.json` файлини яратинг — **бу файл git'га тушмайди**,
   `config.json` эса тушади, шунинг учун локал созлама шу ерга ёзилади:

   ```json
   {
     "telemetry_enabled": true,
     "team_member": "Алишер"
   }
   ```

3. Токенни қўйинг (`config.json` га ЭМАС):

   ```powershell
   "сервер-токени" | Out-File -Encoding utf8 state\server_token.txt
   ```

4. Текширинг:

   ```powershell
   note telemetry          # «YOQILGAN», ким, сервер, токен «bor»
   note telemetry test     # серверга нима кетишини кўрсатади (юбормайди)
   ```

Ундан кейин ҳар сессия тугаганда ҳисобот ўзи кетади.

### Токен қаерда туради

Токен **`config.json` да ЭМАС** — config GitHub репосида, у ёққа сир чиқмаслиги
керак. Иккита йўл бор:

```powershell
# 1) файл (state/ — .gitignore да)
"сервер-токени" | Out-File -Encoding utf8 state\server_token.txt

# 2) ёки муҳит ўзгарувчиси
$env:CLAUDE_NOTE_TOKEN = "сервер-токени"
```

### Исм қаерда туради

`config.json` → `team_member`. Аммо `config.json` репода — унга ёзилган исм
ҳамма клонларга тарқалади. Шунинг учун заҳира йўллар бор, шу тартибда:

1. `config.json` → `team_member`
2. `CLAUDE_NOTE_MEMBER` муҳит ўзгарувчиси
3. `state/member.txt` (gitignore да — **тавсия этилади**)
4. ҳеч бири бўлмаса — `user@host`

### Сервер ўчиқ бўлса

Ҳисобот йўқолмайди: `state/outbox/` да навбатга тушади ва кейинги
**SessionStart** да ўзи юборилади. Навбат вақт бўйича сақланади, тартиб
бузилмайди. Биринчи хатода тўхтайди — сервер ўчиқ бўлса 500 марта уриниб
вақт йўқотилмайди.

### Буйруқлар

```powershell
note telemetry          # ҳолат: ёқилганми, ким, қайси сервер, навбатда нечта
note telemetry test     # серверга нима кетишини КЎРСАТАДИ (юбормайди)
note telemetry send     # намуна ёзувни ҳақиқатан юборади (синов учун)
note telemetry flush    # навбатда қолганларини юборади
note telemetry backfill # ЭСКИ сессияларни серверга юборади

note paket "Алишер"     # жамоадош учун тайёр zip (шахсий токен билан)
```

### Нарх қаердан чиқди

Рақамга ишониш учун уни текшириб кўриш мумкин бўлиши керак. Шунинг учун
`COSTS.md` да, сессия саҳифаларида ва дашбордда иккита жадвал бор:

**1. Модель кесимида токенлар** — қайси моделда неча сўров, қанча кириш,
чиқиш, кэш ёзиш ва кэш ўқиш токени сарфлангани ва улардан ҳисобланган нарх.
Ишлатилган нархлар ҳам ёзиб қўйилади, яъни ҳисобни қўлда такрорлаш мумкин.

> Амалда энг катта улуш деярли ҳамиша **кэш ўқиш** бўлади: сессия узайган
> сари контекст ҳар сўровда қайта ўқилади. Нархни туширишнинг энг самарали
> йўли — сессияни қисқа тутиш (`/clear`).

**2. Пул қайси ишга кетди** — восита ва скилл кесимида (`Bash`, `Edit`,
`Skill: dataviz`, `Agent: Explore` каби).

Бу **тахминий**: битта сўровнинг нархи ўша сўровда чақирилган воситалар
орасида тенг бўлинади. Аниқ бўлиши мумкин эмас — пулни контекст ейди,
восита эмас. `(тоол ишлатилмаган)` — фақат матн қайтарилган навбатлар.

Скилл ва агент **номи** ҳам кўрсатилади. Бу tool аргументларидан олинадиган
ягона нарса — ва у ном, яъни файл йўли, буйруқ ёки матн эмас.

### Кунлик ҳисоб қандай юритилади

Сессия **қачон қайта ишланганидан қатъи назар, иш қилинган кун** ҳисобланади.

Бу муҳим: сессия ҳафталаб чўзилиши мумкин. Агар уни ишланган кунга ёзсак,
24 кунлик сессия тўлиқ битта кунга тушиб қолади — ва ўша кун «1669 соат
ишланган, $980 сарфланган» бўлиб кўринади. Бу ёлғон: иш ўша куни эмас,
бир ой давомида қилинган.

Шунинг учун ҳар ёзувда `day` — сессия **бошланган** кун (мижознинг маҳаллий
вақтида). Кунлик кесим, диаграмма ва «Бугун» шу бўйича ишлайди.

### Тарих (бошланғич қолдиқ)

`.env` даги `HISTORY_BEFORE` — телеметрия ишга туширилган кун. Ундан
**олдин бошланган** сессиялар «тарих» деб ажратилади:

- асосий ҳисобга, кунлик диаграммага ва огоҳлантиришларга **кирмайди**;
- дашборд тепасида алоҳида блок бўлиб туради (жами сарф, сессия сони);
- рўйхатини `/sessions?tarix=1` дан кўриш мумкин.

Сабаби: улар бир неча ҳафта давомида йиғилган ва тизим ишга тушган куннинг
кўрсаткичларини бузади. Уларни ўчириб ташлаш ҳам тўғри эмас — ўтган сарф
бўлганлиги рост. Шунинг учун бошланғич қолдиқ сифатида турибди.

### Эски сессиялар

Телеметрия ёқилгандан **кейин** тугаган сессиялар ўзи кетади. Ундан олдингилари
серверда йўқ — шунинг учун дашборддаги сумма `COSTS.md` дагидан кам кўринади.

```powershell
note telemetry backfill-dry   # нима кетишини кўрсатади
note telemetry backfill       # ҳақиқатан юборади
```

Нарх **дафтардан** (`state/costs.jsonl`) олинади, транскриптдан қайта
ҳисобланмайди — шунда дашборд ва `COSTS.md` бир хил рақамни кўрсатади.
Буйруқни бир неча марта ишлатса ҳам такрорланмайди: `backfill` ёзуви
сервердаги ўша сессияга оид эски қаторларни **алмаштиради**.

`note telemetry test` — ёқишдан олдин албатта ишлатинг: ўзингиз кўрасиз,
серверга аниқ нима кетишини.

### Жамоага очиқ айтилади

Бу яширин кузатув эмас. Мақсад — кимдир нооптимал ишлаётган бўлса (масалан
битта сессияни ҳафталаб чўзиб контекстни 200K дан юқорида сақлаш, ёки арзон
модель етарли бўлган ишда қиммат моделда ўтириш) буни кўриб, тўғри йўлга
солиш. Ҳар бир аъзо `note telemetry test` билан ўзи ҳақида нима кетаётганини
исталган пайт кўра олади.

## Obsidian билан ишлатиш

`vault` папкаси Obsidian учун тайёрланган — мажбурий эмас, лекин қулай.

**Очиш:** иш столидаги **«Билим базаси»** ярлиғини босиш кифоя — vault тўғридан-тўғри очилади.

Ярлиқ ичида `obsidian://open?path=...` URI бор, шунинг учун Obsidian да бошқа vault очиқ бўлса ҳам, айнан шу база очилади. Иккинчи ярлиқ — **ClaudeNote** — лойиҳа папкасини очади (скрипт, созламалар, `state/`).

Қўлда: Obsidian → `Open folder as vault` → `<клон папкаси>\vault`

Нима тайёрланган:

- **`.obsidian/`** — созламалар (wikilink формати, ўқишга қулай кенглик, қоронғи мавзу) олдиндан ёзилган.
- **Тэглар** — ҳар эслатмада `tags: [ЛойиҳаНоми]`. Чап панелдаги тэг рўйхатидан лойиҳа бўйича фильтрлаш ишлайди.
- **Ҳаволалар** — ҳар эслатманинг охирида `## Боғлиқ эслатмалар` бўлими, ичида `[[wikilink]]`лар. Граф кўриниши ва backlink'лар шулар ҳисобига ишлайди. Ҳаволаларни `claude -p` синтез пайтида ўзи танлайди (`related` майдони), фақат ҳақиқий мазмуний боғлиқлик бўлса.
- **`INDEX.md`** — бош саҳифа вазифасини бажаради, барча эслатмалар жадвали.

Фойдали кўринишлар: `Ctrl+G` граф, чап панелда `Tags`, `Ctrl+Shift+F` бутун база бўйича қидирув.

Obsidian файлларни ўзгартирмайди — уларни VS Code да ҳам, Блокнотда ҳам ўқийверасиз.

## Техник тафсилотлар

**Рекурсия ҳимояси.** `note.py` ичкарида `claude -p` чақиради — у ҳам Claude Code сессияси, унинг SessionEnd hook и яна `note.py` ни чақирган бўларди. Шунинг учун болага `CLAUDE_NOTE_ACTIVE=1` муҳит ўзгарувчиси берилади ва `note.py` уни кўрса дарҳол чиқади.

**Фон жараён.** Hook stdin дан payload ни олади, `state/job-*.json` га ёзади ва алоҳида жараён уйғотиб дарҳол қайтади — сессия ёпилиши кечикмайди.

**Windows жараён байроқлари.** `DETACHED_PROCESS` ишлатилмайди: у консолни бутунлай олиб ташлайди ва ичкарида `claude.cmd` (bat файл, `cmd.exe` талаб қилади) `STATUS_CONTROL_C_EXIT` билан йиқилади. Ўрнига `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP`, ва `claude` чақируви ҳам `CREATE_NO_WINDOW` билан юборилади.

**Консол кодировкаси.** Windows консоли cp1251 — кирилл матн бузилмаслиги учун `sys.stdout` UTF-8 га мажбурланади.

## Заҳира нусхалар

`install.py` `settings.json` ва `CLAUDE.md` ни ўзгартиришдан олдин ёнига `*.bak-YYYYmmdd-HHMMSS` нусха қўяди.
